# AI PT operations

The new PT chat/review Gemini paths require `COACH_AI_DATA_SHARING_CONSENT=true` and a configured `GEMINI_API_KEY`. Default consent is false and responses return 503. Obtain explicit consent before enabling this deployment setting. Push opt-in does not enable AI data sharing.

The minimized chat/review payload contains age, goal type, activity level, training mode, current plan dates/activities/nutrition totals/targets, recent food names and nutritional logs, gym session names/status/duration, current gym schedule names/days, energy/difficulty/check-in notes, activity status/minutes/notes and up to 12 recent chat messages. It omits account email/password, height/weight, device tokens and internal database identifiers. Recorded facts are bounded to seven days, latest ten check-ins and latest twelve messages. AI suggestions never apply a plan or write activity/food logs.

The structured plan generator additionally receives the consented physical profile (age, gender, height, current/goal weight), selected survey activity/meal schedule, preferences, up to ten check-ins, nutrition-target macros and up to 120 suitable foods. Food identifiers are necessary for validating real library selections; food owner IDs, database metadata, account/contact/device data and target identifiers are omitted. New plans use `ai-pt-v1` with summary/day notes/focus/intensity. Five plan attempts per local day are counted atomically, separately from chat/review quota. Model timeout is 45 seconds; failed or expired requests are not automatically reissued as paid calls.

Configure GitHub repository secrets `FITTRACK_API_URL` (including `/api`, matching the existing weekly report workflow) and `CRON_SECRET` (matching the server). `coach-tick.yml` requests `POST /api/internal/coach-tick` every fifteen minutes and supports manual dispatch. GitHub schedules are best effort and can be delayed. For reliable frequent scheduling, configure an external scheduler using the same authenticated endpoint every five to fifteen minutes. No ordinary GET route sends notifications or calls Gemini.

Coach push defaults to disabled, firm tone, three daily events and quiet hours 22:00–07:00 in the profile timezone. Snooze and optional caps 1/2/3/5 persist. A durable event key, atomic daily event budget and atomic five-minute job lease limit duplicate scheduling. Each tick iterates opted-in accounts using a cursor, isolates malformed accounts, processes up to 100 queued jobs and rechecks current effective plans/completion/settings immediately before sending. More frequent runs or a dedicated worker are needed at higher volume.

Activity reminders include the actual sport, scheduled time and minutes; before-activity reminders also include the bounded plan focus. They use the current effective plan and do not make another AI call during scheduling.

Expo tickets mean provider acceptance; receipts mean the downstream provider reported success. Neither means guaranteed device delivery. `POST /api/coach/opened` with `{jobId}` records user opening independently. Device-not-registered responses revoke only that user's token. Partial chunk outcomes and previous tickets are retained; transient errors retry up to five attempts within event expiry. Network failure after an unknown handoff, worker crash or lease expiry can still duplicate a push. Exactly-once delivery is not claimed.

Real device validation requires an EAS project ID, FCM/APNs credentials and a built app/device. Automated tests mock Gemini and Expo and do not verify provisioning or physical delivery.

AI requests persist unique user/request-ID claims, completed results and failures. Same-ID replay returns the stored result; different input conflicts. Pending claims are never automatically recycled. Terminal failures include `error.details.code = COACH_REQUEST_FAILED` and `retryable = true`; a deliberate new attempt uses a new ID. Unknown network outcomes retry the existing ID. Daily AI quota is twenty attempts with a twenty-five-second response timeout. Timed-out provider calls cannot currently be cancelled and a new explicit attempt may incur another provider call.
